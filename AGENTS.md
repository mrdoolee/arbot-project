# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository. (CLAUDE.md 와 같은 내용을 유지한다 — 고칠 때는 둘 다 고친다.)

## What this is

"아르봇(ARBOT)" (ARgument chatBOT): a classroom tool for Korean middle/high school science. Students chat with an AI tutor character that coaches Toulmin-style argumentation (Claim → Evidence/Grounds → Reasoning/Warrant) with Socratic questions; the teacher configures the AI, then reviews an automatic argument analysis. Product text is Korean; keep UI copy in Korean.

## Architecture (read this before changing anything)

There is **no application server**. Two deployable pieces talk over HTTP:

1. **Static frontend** (`public/`, served by a trivial Express `server.js`; any static host works). One shared deployment is meant to serve every teacher.
2. **Backend = one Google Apps Script web app per teacher** (`gas-source/Code.js`), bound to that teacher's Google Sheet. The Sheet is the database; Gemini is called from GAS via `UrlFetchApp`. The Gemini API key lives in the Sheet (`환경설정` tab B1), never in this repo or on the Node server.

How the frontend finds its backend: `public/js/gasClient.js` stores the teacher's GAS `/exec` URL in `localStorage`. The teacher console (`index.html`, the site root) generates a student link/QR of the form `student.html?gas=<encoded GAS URL>`; the student page is deliberately a separate path and has no link back to the teacher console (`/teacher.html` just redirects to `/`); opening it saves the URL in the student's browser (**only `student.html` reads `?gas=`** via `GasClient.adoptGasUrlFromQuery`; the console ignores it — see Security model). All API calls go through `GasClient.callGet/callPost`.

**API contract / CORS constraints** (GAS cannot set headers or answer OPTIONS): **every call is a POST** whose JSON body is sent as `Content-Type: text/plain` (a simple request, no preflight). `doGet` only answers a one-line status and never runs an action, so the PIN and the access code can never end up in a URL. The routing key is **`_action`**, not `action` — the persona field "행동 지침" is itself named `action`, and using `action` for routing once caused the two to overwrite each other on save. Actions live in `routeAction()` in `Code.js`, in three groups: **teacher-only** (`TEACHER_ACTIONS_`, need `pin`): `teacherAnalyze`, `getChatOverview`, `getTeacherSettings`, `saveTeacherSettings`, `getProfiles`, `saveProfile`, `deleteProfile`, `saveTopicSetting`, `listGeminiModels`, `testGeminiModel`, `getTopicMaterials`, `saveTopicMaterial`, `getApiKeys`, `saveApiKeys`, `resetApiKeyStatus`, `setTeacherPin`, `getAccessCode`, `setAccessCode`; **student entrance** (`STUDENT_ACTIONS_`, need `accessCode`): `getInitialData`, `processChatMessage`, `getSessionFeedback`; **public**: `testConnection` (checks the PIN itself and returns `pinSet`/`needSetup`/`authorized`; `sheetName` and `sheetUrl` only when authorized, used by the 스프레드시트 접속 button).

**Security model** (read before touching auth): the GAS URL is public to students (it is in the link/QR), so several gates stand in front of it.
1. **The teacher PIN is mandatory.** With no PIN every teacher-only action is refused (`needSetup`), and the PIN can only be created from the **sheet menu** `🔐 교사 비밀번호 설정` (`setTeacherPinFromMenu`; only someone who can open the sheet can run it; it also creates the first access code). The web `setTeacherPin` only *changes* an existing PIN and needs the current one. Min 8 chars; SHA-256 + salt in Script Properties (never in the sheet); a wrong PIN sleeps 800 ms; there is deliberately **no lockout** (a student could lock the teacher out). Forgotten PIN: run the menu item again (or `resetTeacherPin` in the editor, which re-locks everything until the menu is used). The console stays locked until `testConnection` says `authorized`; the PIN lives only in the console tab's `sessionStorage` and teacher requests are POSTed.
2. **수업 입장 코드 (access code)**, Script Property `STUDENT_ACCESS_CODE`. Auto-generated (6 chars from an alphabet without I/O/0/1) at PIN setup or the first teacher read; the teacher can regenerate it or set 6–12 chars of `[A-Z0-9]` (short numeric codes are refused: guessable). Compared case/space/hyphen-insensitively; stored in plaintext because the teacher has to show it. `routeAction` checks it for `STUDENT_ACTIONS_` **first**: no code stored → fail closed; wrong code → 1 s sleep. Changing it invalidates old links at once (a student already in a chat gets "코드가 바뀌었어요" and the composer locks). The student page keeps the code in memory only and sends it with every request (stateless: no session tokens in CacheService that could be evicted). Both the PIN and the code survive `resetSheetToDefaults_`.
3. **Entrance validation** (`validateChatRequest_`, called from `routeAction`, not from `processChatMessage`): question 1–1000 chars; class/group/topic must be in the sheet lists and are **rewritten to the sheet's spelling** (so whitespace/case variants cannot dodge the banned-word counter); history sanitized (≤ 60 items, ≤ 6000 chars each); rate limit 20/min per group and 200/min overall (`rateLimited_`, CacheService fixed window, approximate).
4. **API keys never leave the server in clear.** `getTeacherSettings` returns `AIza••••1234` (+ `geminiApiKeySet`); `getApiKeys` returns the same mask plus an `id` (MD5 of the key, cannot be reversed). A masked value coming back means "unchanged" (`isMaskedKey_`); `saveApiKeys` keeps stored keys by `id`; `testGeminiModel`/`listGeminiModels` accept `keyId`. Gemini is called with the header `x-goog-api-key`, never `?key=`; `maskSecrets_` still scrubs error text; nothing key-related is logged.
5. **Front end**: the console ignores `?gas=`; `GasClient.setGasUrl` only stores `https://script.google.com/.../exec` — which **cannot prove the script is the teacher's** (anyone can host a script on script.google.com), so the link/QR must be handed out by the teacher. Both pages carry a CSP `<meta>` (connect-src = self + script.google.com + script.googleusercontent.com; no eval, no external scripts; `'unsafe-inline'` stays because the scripts are inline) and `referrer: no-referrer`; `qrcode.js` is vendored in `public/js/` (MIT, qrcode-generator 1.4.4, no CDN); `server.js` adds nosniff / X-Frame-Options / Referrer-Policy (put the same headers on any other static host). All student/AI/analysis text is escaped (`escapeHtml` in the console, `textContent`/`esc` on the student page); `tests/frontend_static.test.js` guards this.
6. **Blocking**: an AI `[강제차단]` blocks that group for **10 minutes** (`AI_BLOCK_COOLDOWN_MIN_`, survives reloads); 3 banned-word strikes block the whole day. The time limit is only enforced in the browser.

**Sheet layout** (cell addresses are hard-coded in `Code.js`; changing them means changing both sides):
- `환경설정` (A = label, **B = value**, C = memo; only column B is read): B1 Gemini key, B2 backup sheet ID (optional), B3 chosen Gemini model (empty = auto). **The layout was compacted before the first real deployment**: the former B2/B4 (PDF folder / report-export folder IDs, features removed) and the old row positions B3/B5 no longer exist, and there is **no compatibility or migration code** for sheets in the old layout — a sheet made with the old layout must be converted by hand (delete rows 2 and 4 of `환경설정`, rows 1–9 of `기본설정`, column B of `루브릭 세부설정`, then fix the labels in A) at the same time its GAS is redeployed. Once teachers are using sheets, a layout change needs a migration.
- `기본설정` (sheet-wide settings only; A = label, **B = value**, C = memo): B1 banned words, B2 class list, B3 group list, B4 topic list (comma separated); there are no other rows. Do **not** delete or insert rows in `환경설정` or `기본설정` — the cells are addressed by fixed position (hide rows instead). **All of those addresses are defined once, as the `ENV_*_CELL_` / `CFG_*_CELL_` / `*_RANGE_` constants at the top of `Code.js`** (a test fails if a literal `getRange("B3")`-style address appears elsewhere); to move a cell change the constant, the `Guide.html` 시트 구조 table and `tests/gas_harness.js`. The old `논증평가설정` and `대시보드` tabs are unused (only the reset menu deletes them).
- **Per-topic settings, one tab each** (row 1 = header, every row below = one set; **a blank cell in a non-base row follows the base row of the same tab**; a topic with no row uses the base values; names are matched whitespace/case-insensitively via `normalizeTopic_`):
  - `페르소나 세부설정`: `[이름, 템플릿(socratic|cer|advanced|debate|qna), 역할, 행동 지침, 절대 제한, 예외 대처, 추가 참고, 캐릭터 ID, 캐릭터 이름, 첫 인사말, 구분]`; row 2 is the base row named `기본` (cannot be renamed or deleted). Rows with `구분 = 템플릿` are the **pre-filled template originals** (see below).
  - `루브릭 세부설정`: `[이름, 평가자 역할, 요소별 판정 기준, 종합 평가 루브릭, 피드백 작성 지침, 구분]`; row 2 is `기본`; `구분 = 템플릿` rows are template originals (4 of them: no rubric for `qna`). (The old unused column B "(미사용) 권장 템플릿" was removed from `RUBRIC_COLS_`/`RUBRIC_HEADERS_`.)
  - **Template originals** live in `gas-source/Templates.js` (`TEMPLATE_PROFILES_`, the single source of the template prompts; generated once from the old `PRESETS`). `ensureProfileTabs_()` → `seedTemplateRows_()` appends them to the two tabs with `구분 = 템플릿` the first time it runs on a sheet and records it in Script Property `PROFILE_TEMPLATES_SEEDED` (= `TEMPLATE_SEED_VERSION_`), so a template row a teacher deletes by hand is not resurrected; bump the version to add new templates (only missing names are appended; a teacher's own row with the same name is never overwritten or marked as template). Editing `Templates.js` does **not** change rows already in a sheet. (So the old character pairs that earlier sheets hold — 찬반 토론형=`coach`/비판적 사고 코치, 탐구 도우미=`labcoat`/실험 가운 과학 선생님 — stay in those rows; `ArguShared.resolveCharacter` shows them as the new pair, see Persona templates.) `saveProfile` refuses to modify/rename and `deleteProfile` refuses to delete a template row (the `구분` value cannot be set through the API); the console turns an edit of a template into a **new draft** named `<이름> (수정)` that is saved as a separate row, so templates stay pristine and directly usable.
  - `주제 세부설정`: `[주제, 페르소나 이름, 루브릭 이름, 제한 시간(분), 기억할 대화 쌍]`; row 2 is `(기본)` and only carries the default time limit (fallback 20) / memory pairs (fallback 3). A persona whose template is `qna` always means "no rubric"; `없음` in the rubric cell also means no rubric. **Every topic in the 주제 목록 (`기본설정` B4) has a row here**, so it can be configured in the sheet: `syncTopicRows_()` appends a row with blank cells (blank = follows `(기본)`, so behaviour is unchanged) for every listed topic that lacks one, and deletes the rows of unlisted topics **only when all four cells are blank** (a row with any value is kept and the console shows it as 연결 안 됨). It runs when `saveTeacherSettings` receives `topicList` (the result goes back as `topicRows: {added, removed, error?}`, which the console shows after saving the list), when `getProfiles` loads the 주제 연결 tab, and from the sheet menu `🔄 주제 세부설정 맞추기` (`syncTopicRowsFromMenu`, for a list typed directly into the sheet; there is deliberately no `onEdit` trigger). It never runs on the student path, takes the script lock itself (call it outside any lock), clears the settings cache when it changes something, and never throws: a failure is reported and the list save still succeeds (`getProfiles` adds a warning). `saveTopicSetting` keeps the row of a listed topic when its values become the defaults or on `remove:true` (it just blanks the cells, `{reset:true}`) and deletes the row of an unlisted topic (`{removed:true}`). `readTopicList_()` is the single reader of the list (trim, comma split, de-duplicated by `normalizeTopic_`).
  - The model stays one per sheet (`환경설정` B3, empty = auto) — there is deliberately no per-topic or chat/analysis model split.
- `API키` (created on first save): extra Gemini keys `[이름, 키]`, tried in order after the primary key (B1).
- `탐구자료` (created on first save): one row per topic `[주제, 실험 과정, 준비물, 유의사항, 교사용 메모]`. `processChatMessage` appends only the row matching the student's `topicValue` (whitespace/case-insensitive match, 6 h CacheService cache cleared on save) to the system prompt, so groups on different topics never mix and token cost does not grow with topic count. Limits: 1500 chars/field, 3000 total. Saving an all-empty row is rejected; deletion needs `remove:true`.
- `채팅기록`: appended rows `[date, time, class, group, topic, student text, AI reply or status, persona name (H), rubric name (I)]` — the persona/rubric that applied to that topic *at that moment* (`recordRow_`); I is `-` when the chat is not evaluated (qna persona or `없음`). Old rows: H=`qna` means not evaluated (the old mode flag), blank H/I means "evaluate with whatever rubric is chosen". `apiAnalyze` uses these to decide which chats a rubric evaluates (see Analysis).
- The old in-sheet analysis/report functions (`runToulminAnalysis`, `exportAnalysisToDoc`), the `대시보드` tab and the sheet-menu entry for them were removed; the web app's `apiAnalyze` is the only analysis path. There is no Drive/Docs code left, so the script no longer needs those OAuth scopes (`appsscript.json` has no explicit scope list; they drop out on the next authorisation).

**Chat flow** (`processChatMessage`): same-day block check (reply containing `[시스템 차단]`) → AI-block cooldown (a `[AI 차단]` row in the last 10 minutes) → banned-word 3-strike path (deterministic, counted from today's rows) → otherwise a Gemini call built from the persona fields of **the persona linked to the student's topic** (`resolveTopicConfig_(readCoreConfig_(), topicValue)`; the server looks it up by topic, so nothing the student page sends can pick a persona). `readCoreConfig_` caches the persona + topic tables for 5 min (`cfg_core_v1`, cleared by every settings save; a hand-edit of the sheet shows up within 5 min); the rubric table is only read for analysis/console. Gemini calls go through `geminiGenerate_()`: model = `환경설정` B3 if it looks like a model name, else auto-detected from the models this key can actually call (`pickAutoModel_`: `gemini-flash-lite-latest` first — light and kind to the free-tier quota — then the newest non-preview Flash-Lite, then `gemini-flash-latest`, then the newest Flash; image/embedding/audio models are skipped; the result is cached 6 h under `auto_model_v2`, bump the number when the rule changes). The prompts and rubrics were validated on `gemini-flash-latest`, so answer quality on Flash-Lite (instruction following, "never give the answer", `[강제차단]`) must be re-checked; a model chosen in the console (B3) always wins. Free-tier quotas are per project **and per resolved model** (an alias counts against the model it currently points to), and a 404/"no longer available" retries once with the auto model. Google retires models without notice, which is why the console has a model picker. **Multiple API keys**: `geminiGenerate_` tries the primary key (B1) then the `API키` tab keys; on 402/credits-depleted/quota (`exhausted`, 3 h rest), 429 rate (`rate`, 2 min), or a bad key (`invalid`, 1 h) it rests that key (CacheService, keyed by an MD5 of the key — raw keys are never cache keys) and moves to the next; key-independent errors (5xx, safety block, model problems) are returned as is. When every key fails the error carries `allKeysExhausted` and the student sees "지금은 AI를 사용할 수 없어요" while the teacher's analysis error says to add/refill a key. Saving keys or pressing 쉬는 중 해제 clears the rest flags so a refilled key is used immediately. Off-topic blocking is **not** counted in code: the model emits a `[강제차단]` tag by itself, so it is controlled only by the persona prompt text and has been fragile. **Session feedback** (`getSessionFeedback`, a student action): when the timer ends the student page shows the template's `ArguShared.STUDENT_COPY[tpl].wrapUp` in the 오늘의 탐구 요약 card (so a debate topic is not told to write an 실험보고서) and, if the student said anything (`S.turns > 0`, after any in-flight reply has landed: `S.inflight`), asks for feedback of at most 100 characters (`FEEDBACK_MAX_CHARS_`; the prompt names the template's focus `FEEDBACK_FOCUS_[template]`, the server trims the output with `clampFeedback_`), shown as a 💬 오늘의 피드백 bubble via text nodes. It goes through the same code check, list/rate-limit validation and history sanitising as chat (`validateChatRequest_(p, true)` skips only the question), calls no AI for an empty chat or a blocked group (`groupBlockedReply_`, shared with `processChatMessage`), and is **not written to `채팅기록`** (so it never mixes into analysis or counts); a failure or an old GAS just shows nothing.

**Analysis (`apiAnalyze(class, group, topic, useMaterial, rubricName)`)**: the rubric is chosen by name — the request's `rubricName`, else the topic's current rubric (if the topic is now a no-rubric/qna one, the rubric of the latest evaluated chat). Only chats recorded with that rubric (plus old chats with no rubric name) are analysed; chats recorded with other rubrics are counted in `otherRubrics` (`{name, count, exists}`) so the console can offer "analyse the N chats done with rubric X" (a rubric deleted/renamed since is shown as unavailable), and not-evaluated chats are counted in `excludedQna`. The response also carries `rubricName`, `currentRubricName`, `rubricFallback` (the topic's rubric name did not exist → base used), `templateKey` and `levelMax` so the result view never reads the settings form. One Gemini call returns per-utterance judgments, `contexts` (non-overlapping runs of utterance numbers = one argument context, with title/linkage/evaluation, guided by `CONTEXT_GUIDE_` which also tells the model to weigh context connectivity in the level and feedback), `contextSummary`, and `materialUsed` (the topic's 탐구자료 row is added to the prompt unless the console sends `useMaterial:false`). The console normalizes contexts and computes 완결/부분/단편/비논증 itself from the judged elements (claim+evidence+warrant in one context = 완결), draws them as bands in the flow chart, and falls back to a date/claim-based split when the backend returns no contexts. Judgments can differ between runs on the same chat (LLM variance). Validity findings baked into the prompts (from two rounds of subagent evaluation on synthetic gold-labelled chats; re-verify after any prompt or model change): `CONTEXT_GUIDE_` makes the overall Level a per-context maximum (elements scattered across contexts/days are not merged), tells the model that "(AI 조언: …)" lines are the tutor's words so echoing them is `[판단 유보]` "(AI 조언 복창)", and each utterance may carry `elements` (all elements it contains) besides the single `judgment`; every preset's `rubricCriteria` has anti-inflation rules (length/fluency is not evidence, content-free "근거는 제가 본 것입니다" is `[판단 유보]`, `[한정어]` needs a concrete condition), and `rubricLevel` requires lower levels' elements before a higher level. Level is a structural measure: it does not judge scientific correctness (the analysis tab's "탐구 자료" option only adds comments).

**Persona templates**: the five templates (소크라테스 발문형, CER 코치형, 고급 논쟁형, 찬반 토론형, 탐구 도우미) are rows in the sheet (see Template originals above), so they appear directly in the **편집할 페르소나 / 편집할 루브릭 dropdowns**, which are grouped 기본 / 템플릿 / 내가 만든 것; the `PRESETS` object in `public/index.html` now only holds the description shown in the 템플릿 설명 modal (name, tag, text) and the modal's "이 템플릿 열기" button just opens the template rows (`pickTemplate`). Picking a template never touches the sheet. The teacher links topics to a saved persona/rubric in the 주제 연결 tab (`saveTopicSetting`). Persona and rubric editors are **paired**: selecting a saved persona also opens the rubric with the same name (templates share one name), and vice versa, unless the other editor has unsaved edits. The persona's `대화 방식(템플릿)` is a real switch, not a label: it decides the student guide steps/starters (`ArguShared.STEPS`), whether the persona is `qna` (no rubric, excluded from analysis, material required), the default greeting, and the flow-chart depth of an analysis (`templateKey` in the response comes from the persona the analysed chats were held with); the console shows these under the dropdown (`renderTplEffect`). **Characters are 1:1 with templates** (`ArguShared.CHARACTERS[].template`): 소크라테스 발문형=`socrates`, CER 코치형=`labcoat` (실험 가운 과학 선생님), 고급 논쟁형=`coach` (비판적 사고 코치), 찬반 토론형=`debater` (토론 파트너, headset + 찬/반 speech bubbles), 탐구 도우미=`robot` (과학 조교 로봇); `Templates.js` seeds the same pair and a static test compares them. The picker in the console stays (a teacher may still choose another character), but the pair is the default everywhere: changing a persona's `대화 방식(템플릿)` swaps the character and its name along with the greeting **only if the teacher has not chosen/renamed them**, the card of the current template's pair is badged, and 캐릭터 기본값으로 초기화 resets to the pair. `ArguShared.resolveCharacter(templateKey, id, name)` is the single rule used by the student page and the console for what is shown: an unknown/blank id → the template's pair, and the old seeded mismatches (`debate`+`coach`+이름 비판적 사고 코치 or empty, `qna`+`labcoat`+이름 실험 가운 과학 선생님 or empty) → the new pair (an old pair the teacher renamed is kept; sheets are not rewritten, which is why this works without redeploying a teacher's GAS). A name that is **another character's default name** (e.g. 토론 파트너 drawn with the name 비판적 사고 코치) is treated as a leftover and shown as the character's own default name. **Blank character cells** follow one rule on both sides, `ArguShared.personaCharacter(row, base)` (console) and `inheritCharacter_` in `resolveTopicConfig_` (server → student page): a persona row with a blank 캐릭터 ID whose template differs from `기본` gets **its template's pair**, not the base row's character (blank cells otherwise follow `기본`); a row with a 캐릭터 ID but a blank 캐릭터 이름 gets **that character's name**, not the base row's name; with the same template as `기본`, blank cells still follow `기본`. `gas_profiles.test.js` compares the server + student-page result with `personaCharacter` for 44 base/row combinations, so change both together. The student entrance texts follow the **template, not the character**: `ArguShared.STUDENT_COPY[template]` (`hero` line in the top card, `tutor` line under "○○가 함께해요", `states` for the avatar status label; also used by the console preview) — the tutor line used to be a Socratic sentence shown for every non-qna template, which contradicted e.g. the debate opponent. Add a template → add its character, its `STUDENT_COPY` entry and its `GREETINGS` entry (tests fail otherwise). **Default greetings are per template** (`ArguShared.GREETINGS`, `greetingFor`, `isDefaultGreeting`, shared by console and student page and copied into `Templates.js`): changing a persona's template swaps its greeting only if the teacher has not customised it, and the student page uses the template's greeting when the stored one is blank or the old generic default. `debate` = AI plays the opposing side and asks for 입장→근거→정당화→재반박→조건부 정리; its student-guide step names (입장/재반박/결론) differ from the rubric tags (주장/반박/한정어). `qna` (탐구 도우미) is not an argumentation template: the AI answers experiment questions (measurement, why a material is needed, procedure, safety) from the topic's 탐구자료 and never gives results; it carries no rubric and its chats are never analysed, and the qna state is **per topic** (the topics whose linked persona has template `qna`): the console shows a banner + progress bar + "자료 필요" labels for them and confirms on save while a linked topic lacks material. Material is mandatory *per qna topic*: `getInitialData` returns `missingMaterialTopics` (qna topics only) so the student page disables those topics as "준비 중", and `processChatMessage` refuses (no row written, no Gemini call) a qna chat for a topic without material, so the AI never invents procedure. Student-screen wording for non-argument modes lives in `ArguShared.MODE_TEXT`. These prompts were tuned over several test rounds against real Gemini output — edit deliberately and re-test (see Testing).

## Gotchas

- **Verify the Apps Script project ID**: `gas-source/.clasp.json` must point to `1cnls9j0lhJRW33xR6bIf5bDEBRv1z5oNP8XHtloJM0JkGb1noXt9setB` (the script actually bound to the spreadsheet). An earlier similarly named project was cloned by mistake and wasted hours; never match a project by name via `clasp list-scripts`.
- A function name ending in `_` is hidden from the Apps Script editor's Run dropdown.
- The old HtmlService UI (`gas-source/index.html`) was deleted; `doGet` renders no HTML, and `gas-source/Guide.html` (the live 사용 가이드 dialog, see Core tabs below) is the only `.html` file there (`gas_guide.test.js` checks this). The sheet menu `ℹ️ 정보` (`showAbout_`) shows the version (`v2.0 (2026.10)` + `API_VERSION_`) and the data notice (chats stay in the sheet but are sent to the Gemini API; a free-tier key lets Google use them to improve its services); update its version/date text when releasing.
- `saveTeacherSettings` writes only keys present in the request and rejects requests where role, class/group/topic list, banned words, API key and rubric criteria are all empty. The console disables every save until the matching load (`getTeacherSettings` / `getProfiles`) has succeeded. Keep both safeguards: an empty form once wiped the live sheet's settings. The class/group/banned words and the topic list are saved by two separate console buttons (`saveListSettings`); when a send would be all-empty, the console appends the other lists' last loaded values so the guard passes (e.g. clearing the topic list). The API key field is masked (see Security model): a masked value is ignored, a new key must pass `isSafeKey_`, blank clears it; `backupSheetId` must look like a sheet ID. `saveTeacherSettings` still accepts the old persona/character/rubric/time-limit keys and writes them into the `기본` rows. `saveProfile` rejects empty content, duplicate/reserved names (`-`, `없음`, `qna`, `(기본)`), an empty `기본`, renaming `기본`; `deleteProfile` refuses `기본` and anything a topic row uses; renaming cascades to the topic rows (old chat-log names stay).
- **GAS version drift**: the console is one shared deployment but every teacher's GAS is deployed separately (and `clasp push` alone changes nothing live), so the console can talk to an older GAS. `testConnection` returns `version` (`API_VERSION_` in `Code.js`, now 4 = `getSessionFeedback` + per-date analysis; 3 = `getChatOverview`; a response without it is version 1); the console compares it with `REQUIRED_API_VERSION` and shows the "GAS가 옛 버전이에요" card, and `gasClient` turns the old backend's `알 수 없는 action` answer into `err.oldBackend` with a plain message (the 수업 입장 코드 card shows that instead of a raw error). **Raise `API_VERSION_` and `REQUIRED_API_VERSION` together whenever the console starts using a new action**; a static test fails if they differ. An old GAS also ignores the student access code, so students get in with any code until it is redeployed.
- **Core tabs**: `환경설정`, `기본설정` and `채팅기록` are read through `requireSheet_(name)`, which throws a Korean message naming the missing tab instead of `Cannot read properties of null` (tabs that may legitimately be absent — the 세부설정 tabs, `탐구자료`, `API키`, and everything in `resetSheetToDefaults_` — use `getSheetByName` directly; do not "fix" those). Sheet-menu **`📖 사용 가이드`** (`showGuide_`) opens `gas-source/Guide.html` as a modeless dialog (tabs 처음 시작하기 / 시트 구조 / 메뉴 설명 / 주의·문제 해결). It is static text and read-only (no sheet, property or web route). **When you add, rename or move a tab, header or fixed cell, update its 시트 구조 table** — `tests/gas_guide.test.js` compares it with the tab-name constants, `PERSONA_HEADERS_`/`RUBRIC_HEADERS_`/`TOPIC_CFG_HEADERS_`, the `환경설정` B1–B3 and `기본설정` B1–B4 cells (via the `ENV_*`/`CFG_*` constants), the `(기본)` defaults and the menu items. Sheet-menu **`🩺 시트 구조 점검`** (`checkSheetStructureFromMenu` → `inspectSheetStructure_`) is a **read-only** audit for hand-edited or inherited sheets (missing tabs, key/backup-ID/model format, empty/duplicate/over-long lists, headers, missing `기본` rows, empty base role/criteria, dangling persona/rubric links, bad time limits, qna topics without material, over-limit materials, bad extra keys, chat-log rows with empty keys or off-list names, PIN/code missing); it never creates tabs or writes cells, is not routed to the web, and prints no key in clear. Add a check there when you add a sheet rule, and a case to `tests/gas_structure.test.js`. Real Google Sheets returns date/time cells as `Date`; when faking that in a test build the `Date` from the context (`vm.runInContext('Date', env.ctx)`) — a `Date` made outside is not `instanceof` the one `Code.js` sees and the test silently proves nothing.
- `ensureProfileTabs_()` takes the script lock itself, so never call it (or anything that calls it) while already holding the lock — call it first, then lock.
- **Auth lists**: every teacher-only action is in `TEACHER_ACTIONS_` (`Code.js`) **and** `TEACHER_ACTIONS` (`gasClient.js`); `testConnection` is the only intentional difference (it checks the PIN itself). A new student-facing action must be added to `STUDENT_ACTIONS_` or it is reachable without the access code. `frontend_static.test.js` and `gas_security.test.js` fail when the lists drift. Details of the gates are in the Security model above.
- Student text is written to `채팅기록` through `recordRow_`/`cellText_` (leading `'`) so `=IMAGE(...)`-style input is never executed and class/group names like "3-1" are not turned into dates; settings go through `safeCell_`. The CSV export prefixes `'` for the same reason. If Gemini returns no text (error, safety block) `processChatMessage` throws and writes **nothing**; the student page restores the typed text.
- `escapeHtml` in the console escapes quotes because values go into HTML attributes (`data-topic`, SVG `aria-label`, `<option value>`). The backend also normalizes analysis output (`normalizeJudgment_`, `normalizeLevel_`, `parseJsonLoose_`) so a hostile/odd model string cannot reach the DOM unchanged.
- `?gas=` values are accepted only by `student.html`, and only if they look like `https://script.google.com/.../exec` (`GasClient.isValidGasUrl`; the manual address box on the student page uses the same check). That is a format check, **not** proof of ownership: a crafted link pointing at someone else's script would still be accepted, so hand the link/QR out yourself and rotate the access code if it leaks.
- When patching source with shell heredocs or JS template literals, backslashes in regexes have been silently dropped twice. Write regex-bearing code with the Write/Edit tools and re-check it.

## Testing against the live sheet

The offline tests above cover logic; prompt quality and real-Sheets behaviour are only verified against the real deployment with real Gemini calls.
- Before any test that writes settings, save the output of `getTeacherSettings`. Never click save in the console before "불러오기" has completed.
- Use a clearly named test class (e.g. `테스트반D`) for chat rows. The server now rejects class/group/topic names that are not in the sheet lists, so add the test class to the class list first and remove it afterwards. Live calls need the real teacher PIN (console) and the current access code (student page, or the `accessCode` field). Cleanup has been done by temporarily adding a `tempCleanup` action (restricted to class names starting with `테스트`; marked `TEMP-REMOVE`), deploying, calling it, then removing it and redeploying. Don't leave it in.
- To check student-screen states (warning, block, timeout) without writing rows, override `GasClient.callPost` in the browser console with a fake response.
- Logic that must not touch the live sheet (row marking, analysis filtering, auth, save guards, per-topic settings) belongs in `tests/gas_logic.test.js` / `tests/gas_profiles.test.js`; add cases there when you add backend behavior.
- A sheet without the three `세부설정` tabs gets them on the first request, built from the default content (소크라테스 발문형 as `기본` + the template originals); nothing is copied from older cells. If the tabs cannot be created or read (e.g. sheet protection) the backend keeps working from that same default content in memory (`fallbackCore_()`; `getInitialData.settingsFallback` / `getProfiles.fallback` report it, and saving settings fails with the reason).
- Persona changes: run the same scripted student conversation against each preset via `processChatMessage`, then `teacherAnalyze`, and compare against the preset's stated rules.

## Resetting a sheet to defaults
`resetSheetToDefaults_()` (menu entry `⚠️ 설정·기록 초기화…` → `resetSheetToDefaultsFromMenu`, double confirmation: 예/아니오, then type `초기화`) wipes the three 세부설정 tabs (rebuilt as `기본` = 소크라테스 발문형 content + the template rows + a `(기본)` topic row), the 금지어/학급/모둠/주제 lists (`기본설정` B1:B4; the A labels and C memos stay), the old `논증평가설정` and `대시보드` tabs (deleted if an old version made them), all `탐구자료` rows and all `채팅기록` rows (header kept). It never touches `환경설정`, `API키`, the teacher PIN or the backup spreadsheet. It is deliberately **not** in `routeAction`/`TEACHER_ACTIONS_` (the web URL is public to students and there is no way to confirm there); keep it menu-only. `ensureProfileTabs_()` builds re-created tabs from the same default content, so a tab never gets a blank `기본` persona. Tests: `node tests/gas_reset.test.js`.
